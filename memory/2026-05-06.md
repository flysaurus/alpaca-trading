## 2026-05-06 — Trading App Fixes

### XLK/SPY 52-Week Range White Mark — Fixed
- **Issue:** SPY and XLK white mark not showing in 52-week range bar
- **Root cause:** White mark at 100% was being clipped by `overflow-hidden`
- **Fix:** Changed to downward-pointing triangle indicator at bottom of bar, visible at any position
- **Result:** Triangle clearly shows current price position within 52-week low-high range
- **File:** `src/components/EnhancedPositions.tsx`
- **Build:** Compiled successfully

### XLK/SPY Watchlist White Mark — Added
- **Issue:** XLK and SPY watchlist cards didn't have a visual marker distinguishing them from other ETFs
- **Solution:** Added `WhiteDotIndicator` component (SVG white circle on transparent bg)
- **Logic:** Special symbols XLK and SPY now show white dot in top-right corner of their cards
- **Visual:** White dot appears on both live-price and "No data" cards for these symbols
- **File:** `src/components/WatchlistWidget.tsx`
- **Build:** Compiled successfully

### Market Indices & Watchlist — Zero Change Bug Fixed
- **Root cause:** Alpaca SDK `getBarsV2` returned bars with PascalCase properties (`.ClosePrice`) but code read lowercase (`.close`). Also `limit: 2` with `timeframe: '1Day'` didn't reliably return previous-day bars. Result: `prevClose = 0`, `change = 0`, `changePercent = 0%` everywhere.
- **Fix:** Switched to direct Alpaca REST Data API `GET /v2/stocks/snapshots` (`src/lib/alpaca-rest.ts`). Returns structured fields: `latestTrade.p`, `dailyBar.c`, `prevDailyBar.c`.
- **Indices via ETF proxies** (Alpaca doesn't have `^DJI` direct):
  - DIA × 100 → DJIA
  - SPY × 10 → S&P 500
  - QQQ × 3.5 → NASDAQ
  - IWM × 1.5 → RUSSELL
- Yahoo Finance abandoned for market data: 429 on server IPs, CORS in browser. Unreliable.
- User confirmed index bar now shows real non-zero changes.
- During market hours: `latestTrade.p` provides near real-time trade-by-trade pricing, so it works even better than after-hours.

### Order Telegram Notifications Fixed
- **Root cause:** Code only checked `TELEGRAM_CHAT_ID`, ignored `TELEGRAM_BOT_TOKEN`. Also used fire-and-forget `.catch()` which silently swallowed all errors.
- **Fix (`src/app/api/orders/route.ts`):**
  - Now checks both `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID`
  - `await`s `sendTelegramMessage()` and returns `{ ok, error }` in API response
  - Filled orders → `🎯 ORDER FILLED` with fill price, total, timestamp
  - Pending orders → `⏳ ORDER ACCEPTED` with note that fill alert will follow
