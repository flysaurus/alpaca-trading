## Bug Investigation: Duplicate Workouts in Kilimanjaro Dashboard

**Reported by user:**
- Seeing 9 hiking entries on a daily basis
- Same Run from 21 days ago (Apr 15) appears paired with daily entries
- Suspected deduplication failure

**Root Cause Found:**
- DB unique constraint: `UNIQUE (date, workout_type)` where `date` is `TIMESTAMPTZ`
- `parseDate()` preserves hours/minutes/seconds
- HAE sends same workout in multiple exports with slightly different timestamps
- Each gets stored as a separate row because microseconds differ
- In-memory per-request dedup only works within a single webhook payload, not across multiple exports throughout the day

**Fix Required:**
- Add `normalizeToDay()` helper in webhook route to set UTC hours/minutes/seconds/ms to 0
- Apply to workout dates before both: (a) dedup key generation, (b) DB upsert
- This matches the constraint name `unique_workout_per_day`
- **STATUS:** Code change ready but memory flush is blocking file writes. Need to apply after flush.

**Code change location:**
- File: `kilimanjaro-dashboard/src/app/api/webhook/health/route.ts`
- Function: `storeHaeWorkout()`
- Change: `const date = normalizeToDay(rawDate);` instead of raw parsed date
